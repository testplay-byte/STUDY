Welcome. You are (probably) an AI agent picking up the **Study Helper Planner** project — maybe
on a fresh sandbox, with no memory of what came before. This file gives you the complete
picture. Read it fully, then follow the reading order in §2. Total setup time: ~5 minutes.

## 1. What this project is

We are digitizing the user's school textbooks (scanned page images) into a permanent, structured
**digital library** on GitHub, and building study-tracking + (later) a web dashboard on top.

- **GitHub repo = the only permanent home of the project.** The sandbox this agent runs in may
  be wiped at any moment; anything not pushed to GitHub is lost forever.
- **The repo is also the context store.** Any future AI agent (you, again, or a different model)
  can clone the repo, read the docs, and continue with full context — no other handoff needed.
- Current library: **112 scanned pages** from 2 books → 112 faithful Markdown pages, every
  figure described, every formula in LaTeX, every page traceable to its raw scan.

## 3. Binding ground rules (short version — full detail in CONVENTIONS.md)

1. **Fidelity first.** Page Markdown is a verbatim transcription. Never solve, correct,
   translate or summarize. Book typos are preserved and noted.
2. **Figures are sacred.** Every graph/diagram/photo gets a structured description block
   (`### Figure Fk`) + an inline `[Figure Fk]` marker at its position.
3. **FLAT pages.** Pages live directly in the chapter folder — **never** create
   exercise/section sub-folders (explicit user directive, v3). Exercise/section info lives in
   frontmatter + `chapter.json`.
4. **Raw scans are immutable.** `books/<subject>/raw/<BATCH>/NNNN.jpg` — never modify/rename.
5. **One page = one file**, `page-NNN.md` where NNN = the image number. Never merge/split.
6. **Test-first.** Any new batch: convert 2–4 representative pages, QA them, THEN mass-convert.
7. **5-agent waves.** Mass conversion is done by five parallel sub-agents with detailed prompts
   (each gets Task ID, page range, quirks, rules); coordinator audits ≥ 20% afterwards.
8. **Worklog everything.** Every agent appends the same section to `<repo>/WORKLOG.md` AND
   `/home/z/my-project/worklog.md` (template: `---` / `Task ID:` / `Agent:` / `Task:` /
   `Work Log:` / `Stage Summary:`). Report per-page status lines.
9. **Backup rhythm.** Coordinator commits + pushes after: docs changes, pipeline validation,
   every wave, every audit. Not "at the end" — continuously.
10. **Only the coordinator commits** (agents write files + logs; they never git-commit).
11. **When the user asks to improve anything, the docs improve with it.** If you change how
    something works, update `CONVENTIONS.md`/`PIPELINE.md`/`STATUS.md` in the same session.

## 7. Known quirks that WILL bite you (details in CONVENTIONS §6)

- S-2 running headers misprint "[Chapter 7]" — the chapter is **9**. Never record 7.
- M-1 printed page = image + 6; S-2 = image + 10; S-1 = image. Still: read the printed digit,
  never compute `page_printed`.
- Some pages legitimately have `page_printed: null` (openers, front matter) — that's correct,
  don't "fix" it.
- M-1 exercise boundaries in frontmatter are approximate (user says 5 exercises exist; raw
  info may come later). Fix in frontmatter/chapter.json only — never re-split folders.
