## 1. Folder Hierarchy & Naming (v4)

### 1.1 The tree

```
Books/
├── Raw/                                          # ORIGINAL scans — immutable, never touch
│   └── <Subject>/                                # TitleCase book folder (Mathematics, Statistics, …)
│       └── <Original-Chapter-Name>/              # faithful to the printed/book original, e.g.
│           │                                     #   Front-Matter, Unit-01-Functions-and-Graphs,
│           │                                     #   Chapter-08-Set-Theory
│           └── NNNN.jpg                          # NNNN = zero-padded original upload number
├── Formatted/                                    # CANONICAL markdown library (source of truth)
│   └── <Subject>/
│       ├── book.json                             # generated registry (see §7)
│       └── Chapter-NN-<Title>/                   # uniform numbered chapters, e.g.
│           │                                     #   Chapter-00-Front-Matter, Chapter-01-Functions-and-Graphs
│           ├── chapter.json                      # generated page map (see §7)
│           └── page-NNN.md                       # ALL pages FLAT — no sub-folders, ever
└── Digital/                                      # HAND-TYPESET REPLICA PAGES (test edition)
    ├── <BATCH>-page-NNN.html                     # 8 curated pages, FLAT — no subfolders,
    │                                             #   no index.html (batch code disambiguates)
    └── assets/                                   # figure crops from the raw scans
                                                  #   (<BATCH>-<NNN>-fig-<slug>.png + specials)
```

- The **batch code** (`M-0`, `M-1`, `S-1`, …) is the permanent join key tying a Raw folder, a
  Formatted chapter, and a Digital replica page together (`batch:` frontmatter field + `book.json`).
- Mapping table for the current five batches lives in `tools/build-metadata.mjs` (`BOOKS`)
  and in every `book.json` (`parts[].folder` + `parts[].raw_folder`).

### 1.2 ⚠️ THE FLAT-PAGES RULE (user directive, v3)

**Never create sub-folders inside a chapter/part folder.** No `00-intro/`, no `exercise-1.1/`,
no `multiple-choice-questions/`. A chapter's pages are `page-001.md … page-NNN.md` side by side.

- Rationale: the user reviewed the v2 M-1 exercise split (exercise-1.1/1.2/1.3, each holding a
  single page) and rejected it — boundaries were unreliable and split folders hurt navigation.
- Where does exercise/section info live? In each page's frontmatter (`section:`, `exercise:`,
  `content_type:`) and aggregated into `chapter.json` → queryable without folder splits.
- This applies to **future books too**, even if a chapter contains several exercises.

### 1.3 Codes

| Thing | Pattern | Examples |
|-------|---------|----------|
| Subject folder (under Books/*) | TitleCase | `Mathematics`, `Statistics` |
| Subject identifier (frontmatter `subject:`) | lowercase | `mathematics`, `statistics` |
| Batch code (one uploaded scan package) | `<subject letter>-<n>` | `M-0`, `M-1`, `M-2`, `S-3` … `X-0` = front matter ("zero chapter") of book X; `X-n` = n-th chapter package of book X |
| Formatted chapter folder | `Chapter-<NN>-<TitleCase-Slug>` | `Chapter-00-Front-Matter`, `Chapter-08-Set-Theory`, `Chapter-09-Probability` |
| Unit-style books (printed as "Unit") | still `Chapter-<NN>-<TitleCase-Slug>`; the book's own label ("Unit 01") goes in metadata `chapter_label` | `Chapter-01-Functions-and-Graphs` (label "Unit 01") |
| Raw chapter folder | faithful to the ORIGINAL printed/book name, TitleCase-hyphenated | `Front-Matter`, `Unit-01-Functions-and-Graphs`, `Chapter-08-Set-Theory` |
| Page file | `page-<NNN>.md`, `NNN` = zero-padded **image number** (3 digits; grow to 4 only past 999 pages) | `page-025.md` |
| Raw image | `<NNNN>.jpg`, zero-padded 4 digits, copied **unchanged** from the upload | `0025.jpg` |
| Digital page file | `<BATCH>-page-<NNN>.html` (batch code without the dash), FLAT in `Books/Digital/` | `M1-page-025.html`, `S2-page-042.html` |
| Digital asset | `<BATCH>-<NNN>-fig-<slug>.png` (special crops get descriptive names) in `Books/Digital/assets/` | `S1-003-fig-intersection.png`, `M1-023-keyfacts-icon.png` |

Rules:
- Slugs: hyphenated TitleCase (human-readable on GitHub), keep short (≤ ~40 chars), from the
  printed title.
- **Front matter is Chapter 00** in Formatted (`Chapter-00-Front-Matter`) per user
  directive; its Raw folder keeps the original name (`Front-Matter`).
- **Batch ↔ chapter mapping is recorded in `book.json`/`chapter.json`** (`batch:` field, plus
  `folder:` and `raw_folder:`). One batch currently maps to one chapter; if a future upload
  spans several chapters, split it at RECON time and record the image ranges per chapter in
  `chapter.json`.
- Numbers are zero-padded everywhere so lexical order = logical order.

### 1.4 Raw data (immutable)

- Location: `Books/Raw/<Subject>/<Original-Chapter-Name>/NNNN.jpg`.
- **Never modify, rename, re-compress or delete** raw images. They are the ground truth.
- Raw folders mirror the user's uploads exactly (same count, same order) and are named after
  the original printed chapter names (user directive v4).
- Digitized pages link back via `source_image:` — this is the traceability chain
  (page .md ⇄ raw jpg ⇄ original upload number).

### 1.5 Digital edition — HAND-TYPESET REPLICA PAGES (user directive v4.1; test purposes only)

> History: the first generated design (commit 26bc1c0 — "scan pane + plain-text
> transcription", built by `tools/generate-digital.mjs`) was **rejected by the user**.
> Directive: each Digital page must look like an **actual digital version of the original
> textbook page** — a hand-typeset replica, not a viewer.

- **Curated whitelist ONLY (8 pages, user-approved):** `M1-page-001/023/025.html`
  (Mathematics, Unit-01-Functions-and-Graphs; printed = image + 6) · `S1-page-003/005/006.html`
  (Statistics, Chapter-08-Set-Theory; printed = image) · `S2-page-005/042.html` (Statistics,
  Chapter-09-Probability; printed = image + 10). **Adding pages requires the user's OK**
  (the whitelist lives in `tools/check-digital-test.mjs`).
- **Flat layout, batch-coded filenames:** the 8 files sit DIRECTLY in `Books/Digital/` —
  no subject/chapter sub-folders, no `index.html`. Names are `<BATCH>-page-<NNN>.html`
  (e.g. `M1-page-025.html`, `S2-page-042.html`); batch codes disambiguate same-numbered
  pages (S-1 p5 vs S-2 p5) and match how the user refers to chapters.
- **What a page IS:** a self-contained hand-typeset HTML replica of the printed page —
  real text (never plain-text dumps), KaTeX math (`$` inline / `$$` display, CDN +
  auto-render), real data `<table>`s, and **figure IMAGES cropped from the raw scans**
  embedded where they sit on the printed page. Header/footer page furniture is replicated
  per book (Mathematics: National Book Foundation Grade 12 — blue unit ribbon + orange
  corner wedges `#2293fb→#0167ef` / `#f26a0a`, blue labels `#1560d0`, maroon headings
  `#5e0000`, red Key-Facts callout `#ac0000` with cropped crossed-keys icon, blue footer
  ribbon "GRADE 12 | <page> | National Book Foundation". Statistics: Basic Statistics
  Part-II — monochrome cream page, thin-ruled running header, quiet folio footer).
- **Verbatim content — including the book's own typos and misprints.** E.g. the S-2
  odd-page running header prints "[Chapter 7] Probability" (chapter is 9): the replica
  keeps it verbatim. `S2-page-042` replicates MCQs 101–112 and the full 112-answer ANSWERS
  grid as a real HTML table.
- **Figure crops (canonical sources)** live in `Books/Digital/assets/`
  (`<BATCH>-<NNN>-fig-<slug>.png` plus special crops like `M1-023-keyfacts-icon.png`), cut
  from the raw scans with `tools/crop-figure.py` (fractional boxes). Photos (unit banner,
  telecom photo) are stored as `.jpg`; line art stays `.png` — all optimizer-compressed by
  `tools/embed-figures.py`.
- **⚠️ Figures are EMBEDDED as base64 data URIs — never referenced relatively** (user
  review round 3: pages served/copied without the `assets/` folder showed no graphs and
  collapsed floats — "there are no graphs and also there are not proper layout"). Each
  `<img>` carries its full `data:image/png;base64,…` / `data:image/jpeg;base64,…` payload
  so every page renders identically standalone: file://, a lone downloaded file, any static
  server. `src="assets/…"` in a Digital page is a REGRESSION and fails
  `check-digital-test.mjs`. Re-embed after editing an asset: `python3 tools/embed-figures.py`.
- **Each page is self-contained** (inline CSS, inline figures; KaTeX via CDN) with a slim
  toolbar and a colophon linking the original scan (`../Raw/<Subject>/<Chapter>/<NNNN>.jpg`)
  and the markdown source (`../Formatted/<Subject>/Chapter-NN-…/page-NNN.md`).
- **Hand-typeset, never regenerated by a script.** There is no generator: pages are
  typeset from the canonical markdown + scan and edited in place. `Books/Formatted/`
  remains the canonical library; Digital is a test edition. Scope + self-containment +
  links + asset counts are enforced by `bun tools/check-digital-test.mjs` (ALL GREEN required;
  per-page expected figure counts live in its `EXPECTED_FIGURES` map).
- ⚠️ **CSS-scoping rule:** scope custom selectors to the page's own classes (e.g.
  `.run > span`). Bare descendant selectors like `span { … }` leak into KaTeX's internal
  `.base`/`.run` spans and shred rendered formulas.

## 2. Markdown Page Schema

### 1.6 Digital Edition v3 — FULL 112-page library (user directive v4.2)

> Directive (2026-09-04): "let's build the digital versions of all the pages so far … with a
> proper structure of the folders."

- **Structure mirrors Raw/Formatted 1:1:**
  `Books/Digital/<Subject>/<Chapter-Folder>/page-NNN.html`, per-chapter `assets/`, plus the
  library home `Books/Digital/index.html` and machine map `Books/Digital/manifest.json`.
- **Generated, not hand-typed:** `tools/gen-digital.mjs` renders every page from its
  Formatted markdown in the two book design languages (math blue-ribbon w/ orange wedges;
  stats monochrome cream). The 8 hand-typeset exemplars of v4.1 sit in a `HAND_TYPESET`
  list and are never overwritten. Verbatim-content rule of §1.5 still applies to the
  markdown the pages are generated from.
- **Figure crops per chapter:** `assets/<PREFIX>-<NNN>-fig-<n>[-<slug>].png|jpg`
  (PREFIX = M0/M1/S0/S1/S2; n = the markdown `Figure F<n>` number; table-cell figures
  included). The generator embeds crops as base64 data URIs — pages stay fully
  self-contained — and renders an explicit dashed placeholder for any slot whose crop is
  missing, so a figure can never silently vanish.
- **Gates:** `node tools/check-digital.mjs --strict-figures` must be ALL GREEN before any
  push (coverage 112/112, chrome, link resolution, figure integrity vs `figures_count`,
  tree shape, manifest sync). Run `python3 tools/optimize-assets.py` before the final
  regeneration so embedded data URIs stay small.
- **Known artifacts:** KaTeX's hidden MathML spans inflate `documentElement.scrollWidth`
  at narrow viewports — check `document.body.scrollWidth` instead. `rg` hangs on the
  single-line base64 payloads — grep generated HTML with python.

## 3. Transcription Rules (binding)

1. **Verbatim fidelity.** Transcribe all instructional text exactly. Do not solve, simplify,
   correct, translate, summarize, or add interpretations. Preserve original spelling
   (e.g. "George Cantor", "Demorgan's Laws" stay as printed).
2. **Math = LaTeX.** Inline `$...$`, display `$$...$$`. Proper commands (`\theta`, `\neq`,
   `\in`, `\subseteq`, `\cup`, `\cap`, `\times`, `\phi`, `\bar{A}`, `\frac{a}{b}`,
   `\binom{n}{r}`, `^nP_r`, `\ldots`). Preserve printed equation numbering like `(1)`, `(viii)`.
3. **Tables = GFM tables.** Exact cell values; caption/number above as bold text. Wide tables
   keep all columns (split into two stacked tables only if the book itself prints them split).
4. **Figures/graphs/diagrams/photos are NEVER skipped.** Type, caption/number, exhaustive
   description (axes, labels, scales, ticks, curves & shapes, marked points, shading, legend,
   colors, annotations), then one `**Mathematical meaning:**` line. Known from our books:
   Venn diagrams, sin/cos/tan graphs, tree diagrams, spring-oscillation illustration, cover photos.
5. **Exercise numbering exact.** `Q.1`, `(i)`, `(viii)`, options `A)`/`(a)` as printed. Never
   renumber. MCQ options as a list; sub-parts nested. Printed "Ans." lines are transcribed too.
6. **Headers/footers are page furniture** → captured in frontmatter + H1/scan-line only, never
   body paragraphs (running headers, publisher lines, printed page №, navigation chips `← 08 →`).
7. **Colors/highlights:** visually distinguished headings/boxes survive as bold/blockquote.
8. **Illegible text:** best guess + `[illegible]`, details in `notes:`.
9. **Multi-column:** finish column 1, then column 2.
10. **No truncation.** `tools/convert-page.mjs` auto-continues truncated outputs.
11. **Book typos are preserved** and noted in `notes:` (e.g. S-2 Ex 9.39 (iii) prints
    (4/52)(1/52)=1/169 — wrong math, but we digitize what is printed).

## 8. API Concurrency (validated)

The vision API rate-limits concurrent calls (~3 succeed simultaneously; excess get HTTP 429).
`tools/convert-page.mjs` retries with exponential backoff + jitter, so 5-agent waves are safe,
but each agent must convert its pages **sequentially** (one at a time). During sustained 429
storms: back off, then fall back to direct transcription by the coordinator (documented in WORKLOG).
